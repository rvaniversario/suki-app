# Suki — wet market price monitor

A mobile-first PWA showing which goods are a good buy today (fish, meat, eggs, rice, vegetables, fruit,
spices and more) in every Philippine region and market, from the Department of Agriculture's Bantay
Presyo price monitoring. It ranks goods against their usual price, suggests a weekly plan for fish and
meat, shows one market's prices ("My market"), and writes a short AI weekly note per region.
See [docs/SPEC.md](docs/SPEC.md) for the original spec and what changed since.

```
app/        React 18 + Vite + TypeScript PWA (reads JSON from /data)
scraper/    Python scraper: Bantay Presyo source, catalog, analytics, AI notes, Supabase store, alerts
docker/     nginx config and the container's start / daily-scrape scripts
supabase/   SQL migrations: accounts, push subscriptions, price store
.github/    test workflow
data/       generated by the scraper; git-ignored, never committed
```

## Quick start (Docker)

```sh
cp .env.example .env        # optional: fill in what you use (all of it is optional)
docker compose up -d --build
```

Open http://localhost:8080. On the first start the container fetches a year of prices for all 17
regions (about 10 minutes; with Supabase set up it restores in about a minute instead). A region shows
"could not load prices" until its data is in. After that it updates itself every day at 10:00 Manila;
new prices appear without a rebuild or redeploy.

Useful commands:

```sh
docker compose logs -f suki                                   # scraper and nginx logs
docker compose exec suki python -m scraper run --region all   # run the daily update now
docker compose exec suki python -m scraper push               # copy all data to Supabase (seed once)
docker compose exec suki python -m scraper restore            # rebuild an empty volume from Supabase
```

## How it runs

One container runs nginx (serving the app, and `/data` from a volume) and the scraper:

1. **Empty volume:** restore from Supabase if configured and not empty; otherwise fetch the last
   `HISTORY_DAYS` days from Bantay Presyo.
2. **Every day at 10:00 Manila** (`REFRESH_UTC`): re-read the last 21 days for each region (prices are
   often entered late), rebuild the JSON the app reads, write AI notes for regions whose prices changed,
   save what changed to Supabase, and send price drop alerts.

Every optional part (Supabase, AI, alerts) fails softly: errors are logged and the prices still update.

**Hosting:** any host that runs a Docker container with a persistent volume at `/data` (a VPS,
Railway, Render, Fly.io). Set `PORT` if the host requires a specific port. Static-only hosts such as
Vercel or GitHub Pages cannot run the daily scraper by themselves.

## Configuration

All settings are environment variables, read by `docker compose` from `.env`. `.env.example` lists every
one with comments. `.env` is git-ignored and excluded from Docker builds.

| Settings | For | Without them |
|---|---|---|
| `HOST_PORT`, `HISTORY_DAYS`, `REFRESH_UTC` | Port, first-fill history, daily run time | Defaults: 8080, 365 days, 10:00 Manila |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (secret key), `PRICE_DB` | Permanent copy of the price data and AI notes in Supabase | Data lives only in the Docker volume |
| `GEMINI_API_KEY` or `OPENAI_API_KEY`, `AI_PROVIDER`, `GEMINI_MODEL`, `OPENAI_MODEL`, `AI_WEB_SEARCH`, `AI_DAILY_REQUESTS`, `AI_DAILY_TOKENS` | AI weekly notes | No "This week" card |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (publishable key), `VITE_VAPID_PUBLIC_KEY` | Accounts and alerts in the app (build-time) | Account and alert settings show "not set up" |
| `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `APP_URL` (plus the Supabase secret key) | Sending price drop alerts | No alerts sent |

**Supabase keys:** the scraper needs the **secret** key (`sb_secret_...`, or the older `service_role`
key); it bypasses row level security, so keep it only in `.env`. The app gets the **publishable** key,
which is safe in browsers.

### Supabase setup

1. Create a project at supabase.com.
2. In the SQL editor, run the files in `supabase/migrations/` in order. `..._init.sql` is for accounts
   and alerts; `..._prices.sql` is the price store (enough on its own for storage).
3. Put `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` in `.env`, then `docker compose up -d`.
4. Seed it once with the data already in the volume: `docker compose exec suki python -m scraper push`.

For accounts also enable the email (magic link) and Google providers and add the app URL plus
`/settings` to the auth redirect URLs. Generate VAPID keys once with `npx web-push generate-vapid-keys`.

The price tables have row level security with no policies: only the scraper's secret key can read or
write them, and the app never reads them. Size is roughly 250,000 price rows a year.

### AI notes

Per region, in English and Filipino: a short brief (good buys, what to hold off on, weekly movers), up
to three ulam ideas, warnings about the data, one line per market, and (when web search is available)
"why prices moved" with links. Provider code is in `scraper/ai.py`, the notes in `scraper/insights.py`.

- **Provider:** Google Gemini (free tier) by default, OpenAI as an alternative (`AI_PROVIDER`).
  Free-tier models change; if a model is retired or busy, set `GEMINI_MODEL` to another one.
- **Facts only:** the model gets a table of DA prices and computed comparisons; dish costs are computed
  from real prices and unknown ids are dropped. Search sources come from the search results the API
  returns, never from the model's text; without a source the section is left out.
- **Cost limits:** at most one note request per region per day, only when its prices changed (17 a day
  at most), plus a web search only when a good moved 15% or more in a week. Output is capped per
  request, `AI_DAILY_REQUESTS` / `AI_DAILY_TOKENS` stop it for the day, and an out-of-quota answer
  pauses it until the next day. Gemini's free tier refuses web search; it then turns itself off for the
  day and the notes continue.

## Development

```sh
# scraper
pip install -r scraper/requirements.txt
python -m scraper backfill --region all --days 365     # fill data/ (needed by npm run dev)
python -m scraper run --region all                     # daily update
python -m pytest scraper/tests -q

# app (serves ../data at /data)
cd app && npm install && npm run dev
npm test                                               # vitest
npm run test:e2e                                       # Playwright smoke at 390/820/1440 px + offline,
                                                       # on fixture data in app/e2e/fixtures/data
```

`app/.env.example` lists the app's build settings for `npm run dev` / `npm run build`.

## Data sources

Every region uses the same source and method: the DA **Bantay Presyo** market monitoring. A region's
price for a good is the median across its markets, and "My market" shows one market's own prices.

The older PDF scrapers (MIMAROPA from Google Drive, NCR from da.gov.ph) are still in `scraper/` but are
not run. Setting `pdf: True` on a region in `scraper/config.py` switches it back to its PDF report.

**Bantay Presyo** is the DA's public Power BI dashboard (`scraper/sources/powerbi.py`, docs/SPEC.md section 4.3).
It uses undocumented endpoints, so any failure is logged as "source unavailable" and never fails a run.
The scraper only ever queries the price table and never the `ENCODER` column or the contacts table
(`tbl_csw`); a guard in the query builder and a test enforce this.

- One query per region per run, re-reading the last 21 days because prices are often entered late.
- Goods are mapped by `COMMODITY` through `scraper/catalog/bantaypresyo.yaml` (91 goods).
- A market price outside 0.4×–2.5× of the item's 90-day regional median is rejected and logged.
- Regional point for date d: median of each market's latest price from the
  7 days up to d, needing at least 2 markets.
- Every good shows its newest available price, however old, with that price's date. Markets are
  never hidden; each market price carries its date.
- Output: `data/{region}/markets.json` (markets, newest date) and `data/{region}/markets/{code}.json`
  (newest price per good).
- The source swaps latitude and longitude for many markets; the scraper puts them back.

## PDF reports (not used; notes from the 2026 backfill)

These notes are about the MIMAROPA and NCR PDF scrapers, which are kept but no longer run.

- **MIMAROPA** (304 reports, Jan 1 – Nov 12): the full 14-section layout only started in **November**.
  Until October the report had a short meat list (`FISH`, `LIVESTOCK & POULTRY PRODUCTS`: Bangus,
  Tilapia, Galunggong, Pork Ham, Pork Belly, Beef Rump/Brisket, Whole Chicken). The catalog maps both
  layouts to the same items, so the year-long history covers those; November-only cuts (pork chop, beef
  chuck, chicken parts…) show "Not enough history yet" until they have 14 days.
- `Pork Ham` (old) is mapped to kasim and `Pork Belly` to liempo; ranges and prices line up.
- The 4th `Whole Chicken, Local` row continues the old single `Whole Chicken` series (same range), so
  that occurrence is featured. Other duplicate rows are stored under auto ids and left unlabelled.
- Real-file quirks handled: dates without "As of" (Oct 1–6), a page dated Nov 8 inside the Nov 4 file
  (warning, first page wins), `#DIV/0!` / `#N/A` cells, `ml` units.
- **NCR** (315 reports, weekends included): the layout changed in late October (new section names such
  as `FISHERIES AND SEAFOOD`, `PORK`, `CHICKEN`, and new commodity names). Both map to the same ids. Old
  files print the chicken brand in the specification column; "Fully Dressed" there corresponds to the
  new "Unbranded" row. January files close the date with `]`; cells like `n/as`, `+n/a`, `#DIV/0!` are
  treated as not available. Two files lack the pork header and log warnings.
- The 2026 MIMAROPA root folder ID in the spec had one misread character (`I` → `l`); the verified ID is
  in `scraper/config.py`.
